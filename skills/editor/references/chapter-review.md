# Chapter review

## When to use this guide

Use this guide when the author asks to review a single chapter, run a chapter review, or work
through editor notes on a chapter. Checks that need every chapter at once (repeats across chapters,
first use across the book, the chapter sequence) live in `references/book-review.md`.

---

## Setup (ask first, every time)

Ask these before reading anything, and wait for the answers. Do not assume answers from an earlier
session; things change between reviews. Ask if they would like to save and reuse this information.

**Saved setup.** First ask whether the author has a saved review setup file (for example
`Review setup.md`, kept next to the style guide). If they do, find it by name, read each saved
answer back, and ask what has changed; nothing is assumed current until the author confirms it.
Then ask only the questions the file does not answer, plus the ones that change every review (which
chapter, and whether it has come back from an editor). Apply any checks the file turned off or
changed. If they do not, ask the questions below.

1. **Is the book fiction or nonfiction?** For fiction, the review runs in fiction mode (see
   **Fiction mode** below), and question 6 asks for the story bible.
2. **What is the required chapter format?** Ask this before anything else about the files. Ask for
   the sections every chapter has, which are required, their order and headings, any end-of-chapter
   elements (questions, exercises, worksheets, rubrics), and anything else the author wants
   present in every chapter. Once the style guide is found (question 4), compare its Chapter
   format section with this answer and ask about any difference.
3. **Where is the chapter?** Offer three options:
   - **A Google Drive folder.** Ask for the folder link or name, list its contents, and confirm
     which file is the chapter.
   - **A folder on their computer.** Ask for the folder path, request access, and confirm which
     file is the chapter.
   - **Added to the conversation.** Ask the author to attach or paste the chapter, and confirm what
     arrived.
   If the chapter is missing, unreadable, or ambiguous (two files that could be the same chapter),
   say so and ask.
4. **Where is the style guide?** Use the same three options. If the author has none, offer the
   generic style guide template that ships with these skills and ask whether to use it as is.
   Every style rule this review checks comes from the style guide.
5. **Does the book use interview quotes** (quotes from people the author interviewed, checked
   against transcripts or notes)? If yes, ask where the transcripts are, using the same three
   options. If no, skip every part of this guide marked *Interview quotes only*. Quotations from
   published sources are checked either way.
6. **Is there anything to keep track of while reviewing?** For example a glossary, a figure or
   image list, a Further Reading list, a quote log, a canon file for a running example, a story
   bible (fiction), a tools list, or a list of ideas the author is collecting. For fiction, if
   there is no story bible yet, offer to start one from this chapter. For each one, ask where it
   lives and whether this review should propose additions to it. Keep these as the tracking files
   for this review.
7. **What habits or common issues do you know you have?** For example too many rhetorical
   questions, long sentences, a pet phrase, or leaning on one kind of example. Check the style
   guide's Author's known habits list too, and confirm it is current. Each one gets its own check
   in Pass 1.
8. **Optional inputs.** Does the publisher have a house style file (Pass 2)? Does the author keep a
   file of their editor's recurring notes (Pass 3)? Has this chapter come back from an editor
   (Pass 0)?
9. **Does the chapter file use boundary markers, or should the whole file be read?** Some authors
   keep notes, outlines, or old drafts in the same file as the chapter, between start and end
   markers (for example `[START CHAPTER]` and `[END CHAPTER]`). If they use markers, ask what they
   are. If not, the whole file is the chapter; confirm there is nothing in it that should be
   skipped.
10. **Would you like changes made to the files directly?** The default is findings with search
    strings that the author applies. If they want direct edits, suggest the safest method for where
    the files live (see **Making changes** under Working with files), and say plainly when a direct
    edit could cause problems.
11. **Where should backups go?** Every direct edit, and every change to the style guide, a tracking
    file, or the setup file, is backed up first. Ask for a backups location using the same three
    options.
12. **How would you like the findings delivered?** Offer two options:
    - **In the conversation**, one pass at a time.
    - **As an offline review pack**: HTML pages the author can open in any browser with no internet,
      to mark each finding Fix, Skip, or Done and export the marks. Built by `references/offline-review.md`. Useful for working through findings on a plane or away from the computer.

Confirm the answers back in a short list before starting Pass 0 or Pass 1.

**Review the rules first (first run).** If there is no saved setup file, or the author has not
reviewed the rules before, ask whether they would like to review all the rules before the first
review runs. If yes, walk through them one section at a time: each pass and what it checks (with
fiction mode if the book is fiction), then the style guide's rules. For each section, the author
can keep it, turn a check off, change it, or add one. Changes to how the review runs go in the
setup file as the author's settings; changes to how the book should read go in the style guide,
after a backup and the author's yes. Then confirm the final list and start.

**Save for reuse.** Ask whether the author would like to save these answers to reuse in later
chapter and book reviews. If yes, ask where (the same three options), and write a setup file with
one heading per question and the answer under it: fiction or nonfiction, where the chapters live,
the style guide, the chapter format, interview quotes and transcripts, tracking files, known
habits, the optional inputs, the boundary markers, the edit method, the backups location, how
findings are delivered, and any checks the author turned off or changed. Leave out answers that
belong to this chapter only. If a setup file already exists and answers changed, back it up first
and show what changed before writing. `references/book-review.md` reads the same file.

## Working with files

- **Find files by name, not by a stored ID.** If exactly one file matches, use it. If several
  match, stop: show every match with its size and last-modified time and ask which is current. If
  none match, ask before creating one.
- **Back up before every change.** Before any direct edit to the manuscript, a tracking file, the
  style guide, or the setup file, copy the current version to the backups location the author
  chose in setup, under the original name plus a timestamp (`Name_YYYY-MM-DD_HH-MM`). The current
  file keeps its clean name. Confirm the backup exists before editing; if it cannot be made, do not
  edit.
- **Never delete or trash a file.** Retired and duplicate versions go to the backups location.
- **Never edit a file without approval.** Propose additions and changes, get the author's yes,
  then write.
- **The manuscript is the author's.** Findings are proposals with search strings, not edits,
  unless the author chose direct edits or a script in setup. Even then, show each batch of changes
  and get a yes before applying it.

**Making changes.** Suggest the method that fits where the files live, and warn when a direct edit
could cause problems:

- **Google Docs.** Rewriting a Doc through a file connector can drop formatting, comments,
  suggestions, images, and footnotes. Suggest a Google Apps Script instead: delivered as text the
  author pastes into the Apps Script editor, it backs up the Doc to the backups folder first, makes
  targeted find-and-replace edits that keep formatting, logs every change, and reports any search
  string it could not find. Writing a separate revised copy is the other safe option.
- **Word files (.docx).** Edit a copy with tracked changes so the author can accept or reject each
  one, and leave the original untouched.
- **Markdown or plain text on their computer.** Direct edits are safe once backed up. Edit in place
  with exact find-and-replace, not by rewriting the whole file.
- **Pasted into the conversation.** Return the revised text, or the changed passages with search
  strings, for the author to paste back.
- **Anything else** (Scrivener, InDesign, a publisher's platform): do not edit directly. Give
  findings with search strings.

## Offline review pack

When the author chooses an offline review pack, run every pass as written, then hand the findings
to `references/offline-review.md`, which builds the pack and later applies the marks the author
exports. Use one page per pass.

## Rules for every pass

- **Chapter boundaries.** If the author uses boundary markers, only text between the start and end
  markers is manuscript; without markers, the whole file is, minus anything the author said to skip.
  Outlines, notes, and drafts outside the chapter are reference only. Never flag them, never use
  them in a deliverable, and never compare the chapter to an outline.
- **One pass at a time.** Present each pass's findings and get the author's confirmation before
  moving on. Do not run ahead.
- **Every instance, not a sample.** When a problem is found, search the whole chapter and list every
  instance. The author fixes from the list, so an instance left off is a fix that gets missed.
- **Every finding is actionable.** Give each one a number, a search string the author can paste into
  Find, and the suggested change. A flag with no fix stalls.
- **Fixes follow the style guide.** Check every suggested rewrite against the style guide's prose
  patterns before presenting it. If it ends on a preposition, adds filler, or trades one pattern for
  another, rewrite it again.
- **Exceptions stay settled.** Anything the style guide or the author has approved as an exception
  is not flagged again.
- **Say what could not be checked.** Text inside images, locked files, and anything unread is named
  plainly rather than implied to be covered.

---

## How the review runs

0. **Pass 0:** Editor pass (only when the chapter has come back from an editor)
1. **Pass 1:** Style guide and prose
2. **Pass 2:** House style, figures, and tables
3. **Pass 3:** Editor patterns (optional)
4. **Pass 4:** Editorial flags
5. **Pass 5:** Deliverables and tracking files

Then the re-check once the author has made changes.

---

## Pass 0: Editor pass

Run this when the chapter has come back from an editor. Skip it otherwise.

It needs three documents:

1. **Source of truth:** the current chapter. Everything is checked against this.
2. **Editor's returned copy:** their comments and edited text.
3. **The copy sent to the editor:** so a comparison isolates the editor's own changes.

The editor reviewed a snapshot while the author kept writing. Comparing the sent copy with the
returned copy shows what changed; only the current chapter shows whether it still matters. If only
two documents are supplied, say what cannot be determined and ask for the third.

**The governing rule:** the author keeps the editor's change unless they have already rewritten that
sentence. Report each finding with a search string; if the string is found, the edit still applies.

Classify every change, and give the counts before the detail:

- **DONE:** the editor's wording is already in the chapter.
- **TODO:** the original wording is still there, so the edit is unapplied.
- **MOOT:** neither is present; the passage was rewritten or cut.
- **CHECK:** ambiguous, needs the author's eyes.

Filter extraction noise first: running heads, chapter-number templates, bullet glyphs, and table
cells read out of order look like edits and are not.

Quote every editor comment exactly before responding, then take a position: accept, accept but
reframe, or push back. Where a suggestion should be declined, draft the reply. Where a note asks for
content, write the content.

Watch for:

- **Errors the editor introduced:** dropped or wrong articles, stray commas, idioms changed into
  non-idioms, half-applied insertions. Mark them "do not copy" with the correct version.
- **Changes of meaning:** a smoothed sentence can soften a claim. Compare what each version asserts;
  take the improvements, decline the rest, and show the merged sentence.
- **Quote fidelity:** words inside a verbatim quotation never change.
- **Repeated notes:** the same comment in several places is one note. Propose a sweep.
- **Layout loss:** read returned pages visually. Clipped table columns and rows split across a page
  break can lose content that no text export shows.

Deliver an action sheet: status counts, editor changes as a table, each comment quoted with a
recommendation, then what is still open. Get confirmation before Pass 1.

## Pass 1: Style guide and prose

Read the chapter against the style guide in full. The style guide is the checklist: every rule in
it is a check, and no section is skipped. Report findings grouped by style guide section.

Run these checks as part of the pass:

1. **Every style guide rule.** Spelling, the word list, capitalization, punctuation (including em
   dashes and slashes), numbers, lists, headings, references, citations, quotation rendering, and
   any optional section the book uses.
2. **Acronyms.** Within this chapter, flag: an acronym used before its expansion, unless a tracking
   file (such as a glossary first-use tag) shows it was defined in an earlier chapter; an acronym
   never expanded; an acronym re-expanded that was defined in an earlier chapter; a second expansion
   in the chapter; the full form used after the acronym is established; and wrong casing in the
   expansion. When an acronym is undefined, give the expansion and a plain definition with the flag.
   Where earlier-chapter evidence is missing or doubtful, say so and leave the cross-chapter call to
   `references/book-review.md`.
3. **Defined terms.** Each is bold on its defining sentence and nowhere else in the chapter, and
   never in quotation marks.
4. **Audience and person.** Flag every place the "you" drifts off the core reader (suggest a
   callout), and every shift in grammatical person within a passage. Say whether the shift makes
   sense and give the fix. Report which person the chapter uses most.
5. **Sentence endings.** Every sentence or clause that ends on a preposition or on a stand-in "do."
6. **Repetition.** Everything in the style guide's Repetitive phrasing section, within the chapter:
   repeated openers, ordinal scaffolding, pet phrases, repeated frames, echoes, overused words,
   repeated points, and repeated sentence shape. For overused words, tally content words and
   two- to four-word phrases across the chapter and report the top of the list with counts, so a
   word used twelve times shows up even when no two uses are close together.
7. **AI tells.** Every pattern in the style guide's AI tells list.
8. **Signposting.** Every instance the style guide does not allow.
9. **Filler and wordiness.** Every instance, not only repeats.
10. **Vocabulary and register.** Vague or colloquial words with a more precise alternative, and
    comparisons or thresholds left unresolved.
11. **Author's known habits.** One check per habit the author named in setup or listed in the style
    guide. For a habit like rhetorical questions, count them per section, list each one, say which are
    doing real work, and give a statement or example for the rest. Report each habit separately with
    its count.
12. **Common issues worth checking even if not listed:** rhetorical question clusters, very long
    sentences and paragraphs, passive voice that hides who acts, hedging in front of instructions,
    a run of examples all from the same kind of company or person, and the same transition word used
    throughout. Report a pattern only when it recurs; ask whether to add it to the known habits list.

Exclusions for checks 5 to 12 follow the style guide's Prose patterns section. Per the rules for
every pass, list every instance with a search string and its own rewrite in the author's voice, and
vary the fixes rather than trading one habit for another.

**Tracking: glossary** (if the author tracks one). Collect every acronym and technical term the
chapter needs defined. For each one missing from the glossary, draft an entry in the style guide's
glossary format with a plain definition for the core reader and a first-use tag for the chapter
where the term truly first lands in the teaching content. Present the list, then write the approved
entries.

## Pass 2: House style, figures, and tables

If the publisher has a house style file, check the chapter against it and number the findings.
Without one, run the items below as written.

1. **Language and conduct:** American English (or the book's spelling), no Latin abbreviations, and
   nothing that disparages a group.
2. **Quotes and permissions:** quotes from copyrighted sources and public figures may need
   permission even with attribution. Flag for clearance.
3. **Originality:** no patch-writing (reworded copies of someone else's text) and no reuse of the
   author's own published work without clearance.
4. **AI use:** any AI use is declared to the publisher if required, and AI-assisted material is
   checked for accuracy.
5. **Lists:** succinct items, prose bookends, one level of nesting, numbers only for sequences.
6. **Images:** produced images meet the publisher's specifications in the style guide.
7. **Figure and table numbering.** List every caption and every in-text reference, one list for
   figures and one for tables, in reading order. Flag: a caption numbered for another chapter; a gap,
   repeat, or out-of-order number; figures and tables counted as one sequence; a number missing its
   chapter part; a figure or table with no caption; a reference with no matching caption, or one
   pointing at the wrong caption; and a caption the text never mentions. A reference to another
   chapter's figure is fine when that caption still exists there with that number. For each fix,
   list every caption and reference that changes, old number to new.
8. **Image opportunities.** Flag places a visual would teach better than prose: an ordered process,
   options compared on the same axes, a structure or spatial relationship, a before-and-after, and
   anything described as a visual but rendered as text (flows drawn with arrows, diagrams in
   characters). For each, say what it should show, what it teaches that prose cannot, and where it
   goes.

**Tracking: figures** (if the author tracks a figure list). Confirm every figure the chapter
references is in the list with its number, title, and a one-sentence description, plus any image
opportunities the author accepts. Present additions, then write the approved entries.

---

## Pass 3: Editor patterns (optional)

If the author keeps a file of their editor's recurring notes and preferences, apply it to the
chapter and number the findings. Skip this pass when there is no such file. Editor patterns often
overlap with Pass 1 and Pass 4; running this pass first captures the editor's structural cuts and
register preferences, and later passes catch the rest.

---

## Pass 4: Editorial flags

Surface these for the author's review; do not insert changes. Number every flag.

**Content and accuracy**

1. **Fact check:** anything objectively false, and anything that needs a source.
2. **Unsupported claims:** assertions about human behavior or psychology that need a citation. Name
   the claim and suggest finding a primary source.
3. **Citation completeness:** any source named in the text that is missing its title, author, year,
   or publication.
4. **Phrasing too close to a source:** compare every sentence carrying a citation with the source
   where it can be read. Flag any paraphrase that keeps the source's distinctive wording or sentence
   shape, and give both fixes: a direct quote, or a rewrite in the author's words.
5. **Currency:** time-sensitive claims (tools, prices, pay, technology capabilities, laws) that need
   checking before print.
6. **Internal contradictions:** advice in one place that undercuts advice in another.

**Promise and structure**

7. **Promise versus delivery, both directions:** if the chapter format has a front-of-chapter
   learning list, confirm the chapter teaches everything on it, and that the list names everything
   substantial the chapter teaches. Propose any missing entry in the style guide's format.
8. **Introduction alignment:** the opening previews what the chapter actually covers. Flag promises
   the body does not keep and major sections the opening never mentions.
9. **Cross-references and deferrals inside the chapter:** every "later in this chapter," "the next
   section," and named figure, table, or worksheet resolves to something that exists and covers what
   was promised. Flag vague deferrals that name no destination ("later in the book"). References to
   other chapters are listed for `references/book-review.md`, which resolves them against the whole manuscript.
10. **Closing:** the chapter ends with the closing section the format requires, under its fixed
    label, doing all of its jobs (for a Summary: recap, why it matters, and the handoff to the next
    chapter). Name any job that is missing. A closing passage with no heading or a variant heading
    needs the standard label, not a rewrite. The last chapter closes the book instead.
11. **Section headings and structure.** First report the heading outline as a plain indented list.
    Then check: levels follow the style guide; every heading names what is under it; subsections sit
    under their real parent and siblings share a level; the order matches what the opening and the
    learning list promise; no section is long enough to need subheadings and has none, and no run of
    headings is so short it should be one section.
12. **Coherence and actionability:** sections where the argument loses its thread, advice that is
    unclear, or a reader left without a concrete next step.
13. **Concept emphasis:** key concepts that would benefit from distinct formatting or a callout.
14. **Story repetition within the chapter:** any anecdote, example, or statistic used more than once.
    Always a problem: flag the repeat and suggest a replacement.

**Voice and reader**

15. **Voice and tone** consistent with the rest of the book.
16. **Relatability:** personal stories that lean on prestige, status, or circumstances the core reader
    is unlikely to share. Suggest a reframe that keeps the story and widens who it fits.
17. **Scope and inclusivity:** examples, framings, or lists narrower than the point they make.
18. **Humor review:** reading as a professional comedian who understands setup, subversion, timing,
    specificity, and callbacks, name the chapter's tone, flag jokes that do not land, and suggest two
    or three places a joke would help without breaking register.

**Required elements**

19. **Chapter format:** every section and element in the required chapter format from setup is
    present, in order, under its fixed label, with the expected count and format. List what is
    missing and offer to draft it in Pass 5.
20. **Book club question suggestions:** suggest discussion questions a book club could use for this
    chapter, or check the existing set. Each is answerable from this chapter alone; the levels are
    genuinely mixed (recall, application, and position questions); each opens a discussion rather
    than having one right answer; and every major section is reachable. Report as a table:
    question, purpose, verdict (keep, rewrite, cut, or new), and the wording.
21. **Running example continuity** *(if the author tracks a canon file; in fiction mode this becomes
    the story bible check)*: check every detail of the running example (names, screens, people,
    roles, data, numbers, timeline) against the canon file. A match needs no action. A conflict is
    flagged with both forms and a question. A new detail is proposed as an addition with where it
    first appears. Confirm the numbers add up. Check role words in both directions per the style
    guide.

**Risk and access**

22. **Permissions and legal:** sign-offs from interviewees (*Interview quotes only*), real names, and
    fair use on quoted material.
23. **Print risk review:** read the chapter as an unfriendly reader would. Lead with the counts and
    state once that this is not legal advice. For each finding give the location, the sentence, the
    risk, a verdict (CUT, REWRITE, LAWYER, OK AS IS), and the replacement sentence.
    - **Contestable claims stated as universal.** Offer the scoped version ("in my experience," "at
      companies with a written process").
    - **Advice that could leave a reader worse off** if followed literally. Keep it and add the
      condition under which it is a bad idea.
    - **Identifiable people.** Named people, and unnamed people identifiable from role, company, and
      time. A negative characterization needs the detail removed, a composite, or written sign-off.
    - **Named companies.** Keep and cite what is public; frame recollection of internal practice as
      one person's experience, or de-identify it.
    - **Current and former employers.** Unpublished internal process, tooling, or architecture;
      unreleased work; pay, leveling, or performance specifics; named colleagues; the circumstances of
      a departure; and criticism of the culture. Surface these for the author and counsel; never call
      a mention safe because it reads as mild.
    - **Groups and generalizations.** Advice that is safe for a reader in the majority and costlier
      for one who is not. Say so in the text.
    - **Legal, HR, and financial advice in disguise.** Add a hedge or a pointer to a professional.
    - **Tone.** Sarcasm aimed at a real, identifiable party.
    LAWYER items go to the publisher's contact and the author's counsel.
24. **Accessibility:** read the chapter as a screen reader user would hear it. Flag images without real
    alt text (and draft it, ready to paste), tables and code set as images, worksheets that exist only
    as images, meaning carried only by appearance, empty or image-filled headings or skipped levels,
    reading-order problems (runs of images with no text between them, captions separated from their
    images), and text that reads aloud badly (bare URLs, meaningful symbols and arrows).

**Tracking files, in reverse**

25. **Tracking file reverse check:** for each tracking file, check this chapter's entries against the
    chapter. Flag a glossary first-use tag whose term no longer appears here, a figure entry the chapter
    no longer references or whose number changed, an ideas entry pointing at material that was cut, and
    a Further Reading entry for a topic the chapter no longer covers. Say what each should become; where
    the fix belongs in another chapter, name it. Do not edit without approval.

## Pass 5: Deliverables and tracking files

1. **Endnotes.** Classify every inline link: a citation backing a claim becomes a numbered endnote; a
   resource goes to Further Reading if the book has one. Renumber the full set in reading order.
   Confirm every URL removed from the body is accounted for. Resolve every `[citation]`
   placeholder by researching the source, and give a placement list showing where each note number
   belongs.
2. **Endnote audit.** Check every note against the style guide's citation rules for completeness and
   accuracy (the claim appears in the source with the same numbers and population; any quote matches
   word for word). Open every link and record where it lands. Report a table: note number, source,
   link status (OK, REDIRECT, DEAD, BLOCKED, WRONG PAGE), the problem, and the fix. Deliver corrected
   notes as a clean list ready to paste.
3. **Endnote mechanics.** The list runs 1 to N with no restart, blank entry, or skipped number; no
   heading has been swallowed into the list above it; no stray marker from an old numbering scheme
   remains; one citation style throughout; and no leftover draft notes below the chapter end marker.
4. **Chapter title.** The title line and file name match the style guide's format exactly, and the
   title still describes the chapter. Then judge it as a title: it tells the reader what they get,
   sounds like the book rather than a syllabus, and survives being said out loud. Read the other chapter
   titles first so the judgment is against the set. Where it clears accuracy but not voice, propose two
   or three alternates, recommend one, and say what each gives up.
5. **Missing required elements.** Draft anything the chapter format requires that is missing (for
   example the front-of-chapter list, discussion or practice questions), in the format the style guide
   sets.
6. **Tracked items.** Report everything the author asked to keep track of during setup: what was found,
   what was added to each tracking file, and what is still open.

## Fiction mode

When the author says the book is fiction, run the passes as written with these changes. Read the
style guide's Fiction section first; it holds the rules these checks use.

**Pass 1 adds:**

- **Point of view.** Name whose point of view each scene uses. Flag head-hopping, a detail the
  point-of-view character could not know or see, and a switch that breaks the style guide's rule.
- **Tense.** Flag every slip out of the book's tense outside a marked flashback.
- **Dialogue mechanics.** Punctuation, a new paragraph per speaker, said-bookisms, adverbs on tags,
  and any exchange long enough that the reader loses track of who is speaking.
- **Filter words.** Every instance, with the direct version.
- **Show versus tell.** Emotions named that the scene already shows, and emotions named that the
  scene never earns.
- **Distinct voices.** Characters who sound the same, and a character whose speech habits drift
  from the story bible.
- **Repeated beats.** Gestures and tics counted per character (nods, sighs, smiles, looks).
- **Grammar inside dialogue** is voice: fragments, slang, and dialect are not flagged unless they
  are inconsistent for that character.

**Pass 4 changes:**

- **Off:** citation and source checks (2, 3, 4), the learning list (7), and concept emphasis
  (13). Book club questions (20) still apply.
- **Currency (5) becomes anachronisms:** words, objects, technology, prices, and attitudes that do
  not fit the setting's time and place. Fact check (1) still applies to real places, history, and
  how things work.
- **Coherence (12) becomes scene purpose:** each scene changes something (learned, decided, lost, or
  won). Flag scenes where nothing changes, and scene breaks that do not follow the style guide.
- **Pacing:** long stretches of summary, backstory, or description that stall the scene, and
  chapter endings with no reason to turn the page.
- **Story bible continuity (replaces 21).** Check every detail in the chapter against the story
  bible: character names and nicknames, ages (advancing with the timeline), physical details,
  relationships, jobs, and speech habits; dates, days of the week, seasons, weather, travel and
  healing times; places and layouts; who has which object and where it was last seen; world rules;
  and who knows what by this point. A match needs no action. A conflict is flagged with both forms
  and a question. A new detail is proposed as an addition with where it first appears.
- **Print risk (23) still applies** to characters based on real people, real businesses shown in a
  bad light, and real places described as the scene of a crime.

**Pass 5 changes:** endnotes and missing learning elements are off unless the book has them.
Tracked items include the story bible additions.

## After the author confirms changes are complete

Re-check against everything flagged:

- Every flagged item was addressed or explicitly set aside.
- Endnotes run in reading order as plain integers, every superscript has exactly one note and every
  note exactly one superscript, and every removed URL is accounted for.
- All `[citation]` placeholders are resolved.
- Every approved tracking-file addition was written.
- No new story repetition, repeated opener, AI tell, signpost, filler, or known habit was introduced by
  the changes, and no rewrite ends on a preposition or a stand-in "do."
- Every acronym is expanded once, at its first appearance, and used alone after that.
- Headings follow the style guide's levels.
- The chapter has every required element, and the closing does all of its jobs.
- Every CUT and REWRITE from the print risk review was applied, and every LAWYER item was resolved or
  carried forward.

## Changing this guide or the style guide

When the author asks for a change to how reviews run, change this guide. When the change is about how
the book should read, change the style guide instead. Either way: back up the current version, make
the change, and confirm both actions to the author.
